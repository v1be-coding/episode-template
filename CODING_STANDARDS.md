# Coding standards

Read by the reviewer agent (`/code-review`), not by the builder. Judgement calls only: anything a tool can check belongs in a tool, not here. Keep this file short. Add a rule when a review misses something; remove one that only adds noise.

## Don't report

These already run in the pre-commit hook or CI. Skip anything they catch.

- `npm run lint`: ESLint, plus the frozen-test rules in `frozen/`
- `npm run format:check`: Prettier
- `npm run typecheck`: TypeScript
- `npm test`: Vitest
- `npm run secrets`: secretlint
- The frozen acceptance tests in `frozen/`, run by `verify.yml`
- Migrations that remove things: `deploy.yml` refuses them
- Anything in `frozen/`, `drizzle/` (generated) or `package-lock.json`

## Reporting bar

- Report only what you can show: cite `file:line` and say what goes wrong.
- If you're not sure, leave it out.

## Rules

### Every write survives a retry

Any write may run twice. A write must be an upsert keyed by a client-generated ID, inside `transactionWithRetry`.

- Bad: `db.insert(orders).values({ total })`, with the ID generated by the database
- Good: `tx.insert(orders).values({ id, total }).onConflictDoUpdate({ target: orders.id, ... })` inside `transactionWithRetry`, with `id` from the client

Why: a retried plain insert creates duplicates.

### Seed data is fake

`src/db/seed-data.ts` holds made-up data only: no real names, emails or addresses.

Why: it loads on every portfolio site, which is public.

### Comments give reasons, not narration

In the diff, flag a comment that:

- narrates the change, the chat, the plan or an old version ("Updated to use X", "as requested", "removed the old cache")
- doesn't match the code next to it

Outside the diff, flag a comment the change made false: when the diff changes what a function, type or route does, check comments that describe it (at its callers, its definition, and in docs). Cite the comment's `file:line` and the change that broke it.

Don't flag a comment that gives a reason (a constraint, a workaround, an invariant). Don't flag the style of comments the diff didn't touch.

Why: the next agent believes comments over code.
